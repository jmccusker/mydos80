MyDOS/80 HWLINK Tester 0.2.0-E02 - release notes
=================================================

E02, the second evaluation release for testing a real Model 4P from
Linux. E01 (0.1.0-E01) remains available unchanged. Still READ ONLY.

NEW IN E02
- Findings: the report interprets its results (FAULT, WARNING, NOTE,
  INFO), with the measured values, possible causes and the open hardware
  question each answers; a comparison with the trs80gp emulator's
  recorded 4P values and the simulator's model.
- Automatic follow-up: at the end of a test the tester runs the
  read-only checks its own findings call for (a bad sector read ten
  times, a track surveyed again, a RAM range tested again) and adds the
  answers. `followup DIR` repeats them in a later session.
- Recovery: a lost connection (a loose cable, a RESET by mistake, an
  unplugged adapter) is offered a reconnection; the test goes on where it
  stopped without repeating what finished, and each disk is identified
  again first (at most twice).
- `drives`: which physical drive answers to each drive number.
- `--drives 0,1,2,3` and `--cylinders 80` (opt-in) for other drive
  configurations.
- `analyze` reads a results folder or a REPORT.txt alone (E01 reports
  too); REPORT.txt ends with a data block for the analysis tools.
- Faster floppy reads: a track's sectors in two revolutions (E01 needed
  about one revolution a sector); fewer and merged writes to the 4P's
  screen. The full self-test takes about 8 minutes (E01: about 12).
- A connection failure is reported as LINK LOST (E01: ERROR).

WHAT IT DOES
- Native Linux serial: 19200 baud, 8 data bits, odd parity, 2 stop bits,
  no flow control, DTR and RTS on (the 4P ROM serial loader's settings);
  parity and framing errors and driver-counted overruns are recorded.
- The 4P ROM serial loader, the UART probe (the 4P's serial status bits
  measured, nothing guessed), the diagnostics program.
- System: CPU clock, a CPU instruction check, the memory page map, RAM,
  video RAM, keyboard, the clock-interrupt status port.
- Floppy, READ ONLY: the WD1793 controller; per drive selection, READY,
  index pulses, rotation, the motor's stop; where a disk turns: stepping,
  a survey of every track of both sides at both densities, a read of
  every sector the survey found, seek accuracy.

WHAT IT DOES NOT DO
- No disk is ever written or formatted: the write programs are not in
  this release at all.
- No hard disk, FreHD or other storage port is touched; the 4P's memory
  map and CPU speed are not changed; nothing is installed on the 4P.
- A medium is never assumed from READY alone; no geometry is assumed.

HOW IT WAS TESTED (and how not)
- Simulator: the whole test against the built-in virtual 4P through the
  real serial code path, including injected faults, lost connections
  and resets. STATIC evidence, not hardware evidence.
- The packaged release itself was extracted fresh and run as an ordinary
  user on Ubuntu 24.04, Ubuntu 22.04.5 and Fedora 45 (see the release
  page for the exact record).
- NOT yet tested: a real serial adapter, a real 4P (E01's first real
  runs are under way). Expect surprises, and please report them.

KNOWN LIMITATIONS
- The 4P's real UART behaviour is measured by the probe on your machine;
  an unsupported behaviour stops the test with a clear message.
- Floppy data transfers need the 4P's fast (4 MHz) CPU clock, which the
  tester measures; MFM reads are refused otherwise.
- The keyboard test sees only the keys you press during its window.
- A disk is identified after a reconnection by its format (sector IDs)
  and a few sectors' data checksums.
